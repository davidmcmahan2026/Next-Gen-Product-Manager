Bolt + Relevance AI Split

Nine tools, three ways to hold them: five Cleo calls on its own judgment, two it can request but Bolt's gate decides, and two it never sees at all. The diagram below shows where each one lives and who's allowed to reach it.

What changes on each side

Impact on Bolt

Build

  • Seven small API endpoints: Profiler, Validator, Diff/Preview Generator, Audit Logger, Job/Progress open, plus Rules Engine and Workflow Registry gated.
  • The two gated endpoints each start with the same check: look up the approval record for this plan ID; if it's missing, return a refusal instead of running.
  • Parser and Export hidden stay internal functions called only by your own backend code — never registered anywhere Cleo can see them.
  • The Postgres/SQLite tables for approval records and the audit trail — this is the data the gate actually checks against.

Impact on Relevance AI

Configure

  • Register the same five open endpoints as Tools, each with a clear name and description — that description is literally what Cleo's reasoning reads to decide whether to call it.
  • Register the two gated endpoints as Tools too, so Cleo can call them — just don't expect them to succeed without Bolt's approval check passing first.
  • No database credentials, no execution permissions, and no knowledge of Parser or Export — Relevance AI only ever holds the seven tool definitions above and the agent's system prompt.
