Cleo Agent Architecture

One orchestrating agent, five internal reasoning skills, ten deterministic tools — and a single approval gate that decides what Cleo is allowed to execute.

internal reasoning / data flow tool calls & reporting approval-gated path blocked until approval record exists

01Cleo's five reasoning skills

1
Profiling Interpreter
Reads the deterministic profiler's output (types, blanks, duplicates, anomalies) and turns it into a candidate issue list.
2
Recommendation Ranker
Scores and ranks candidate cleanup actions using profiling and validation signals.
3
Anomaly Explainer
Converts validator findings into plain-language explanations, required to cite exact row / cell / rule IDs rather than free-form claims.
4
Confidence Gatekeeper
Scores each recommendation's confidence; anything below threshold is force-routed to manual review instead of offered as auto-approvable.
5
Workflow Drafter
After an approved run, proposes a reusable workflow definition — as a draft only; never writes to the registry directly.

04Guardrails

  • Cleo holds no direct write path to the Rules Engine or Workflow Registry — every mutating call routes through a wrapper that checks for a valid approval record first.
  • Every Cleo-generated explanation must carry structured evidence references (row / cell / rule IDs), validated against actual validator output before display.
  • Tool permissions are scoped per call — read/report tools are open, the two mutating tools are gated — not one broad credential for everything.
  • Confidence thresholds and the approval-checkpoint policy are admin-configurable (Priya's persona), not hardcoded.
